# 프로젝트 문서 관리

## 공통 기준

- 사용자 지시와 기존 프로젝트 규칙을 우선하고 점진적으로 적용한다.
- 해당 프로젝트 루트의 `docs/`에 저장한다. 루트를 확인할 수 없으면 추정하지 말고 위치를 질문한다.
- 대표 문서와 ID를 유지하고 근거·추론·미검증을 구분한다. 대체된 결정은 `legacy/`에 연결·이유를 남겨 보존한다.
- 스킬 사용 자체로 예약 작업, 도구 설치, 외부 업로드, 커밋, 루트 `AGENTS.md` 수정, 다른 프로젝트 변경이 허용되지는 않는다.

## 작업별 읽기

예정된 동작에 해당하는 행의 **절과 하위 절만** 읽는다. 조건이 겹치면 필요한 절을 추가한다. 쓰기 작업에는 [운영][ops]의 **저장 공통과 완료 기준**을 포함한다.

| 작업 | 읽을 참조와 절 |
| --- | --- |
| 조회 / 재개 | [운영][ops]: 조회와 지식 재사용 / 재개와 초기 적용 중 해당 절 |
| 저장·작업일지·진행 갱신 | [운영][ops]: 저장 공통과 완료 기준; 실행 기록은 프로젝트 실행과 기록 |
| 첫 적용·분류/스키마 변경·장부 형식 확인 | [구조][structure]: 저장 범위와 적용 / 층과 소유권 / 관리 기록의 역할 중 해당 절 |
| 문서 생성·ID/메타데이터/관계 변경 | [구조][structure]: 문서의 정체성 |
| 새 자료·지식 반영 | [운영][ops]: 자료·작업 결과 반영: 두 단계 |
| 주장·충돌 / 최신성 / 통합·이동·결정 교체 / 의미 검토 | [근거][evidence]: 근거와 주장 / 최신성과 증분 갱신 / 통합·분리·결정 교체 / 구조 점검과 의미 검토 중 해당 절 |
| 일괄 이동·여러 문서의 연쇄 수정 | [운영][ops]: 일괄 변경과 복구 |
| 자동 구조 점검·통합/이동/결정 교체 완료 검사 | [도구][health]: 실행 / 확인 범위 |
| 방법론 선정 근거·갱신 | [출처][method] |

이번 작업에서 이미 읽은 지침은 변경되지 않았으면 재사용한다. 이 표는 스킬 참조의 읽기 범위이며, 프로젝트 문서·현재 상태·근거는 선택한 절에 따라 실제 파일을 확인한다. 구조 검사로 사실 검증이나 결정 승인을 대신하지 않는다.
