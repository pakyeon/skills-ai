# 근거, 최신성, 문서 생애 관리

새로운 중요한 주장·검증·충돌에는 근거와 주장, 입력 변경·재확인 기한에는 최신성과 증분 갱신, 문서 통합·이동·결정 변경에는 통합·분리·결정 교체, 의미 검토 요청에는 구조 점검과 의미 검토를 읽는다.

## 근거와 주장

**근거와 추론을 구분.** 중요한 주장에는 출처 위치 또는 실제 검증 근거를 남긴다. 직접 추출·계산·추론·미확인은 구분하며 AI가 만든 요약을 독립적인 새 증거로 세지 않는다.

**판단 상태와 최신성을 분리.** 문서가 유효하다는 것, 근거가 충분하다는 것, 원자료가 바뀌지 않았다는 것은 다르다. 최근 작성·조회됐다는 이유로 사실이나 결정의 신뢰도를 올리지 않는다.

독자가 사실로 받아들일 중요한 숫자·날짜·비교·결정 근거에는 출처 위치 또는 실제 검증 결과를 연결한다. 원자료에서 먼저 찾고 작성한다. 정규화한 단위·표기와 계산값은 변환 또는 계산 과정·입력 근거를 남긴다. 존재하지 않는 인용·행·페이지·날짜를 만들지 않는다.

주장의 근거 방식은 다음과 같다.

| 방식 | 의미 |
| --- | --- |
| `EXTRACTED` | 원문 또는 관찰 결과에 직접 존재 |
| `CALCULATED` | 명시된 입력과 계산에서 얻은 값 |
| `INFERRED` | 근거에서 도출한 해석. 원문 사실과 구분 |
| `AMBIGUOUS` | 원문 의미·범위가 불명확 |
| `UNVERIFIED` | 확인할 자료가 없음 |

검토 결과는 `confirmed`, `provisional`, `disputed`, `unsupported`, `superseded`로 따로 기록한다. 직접 추출됐더라도 원문 자체가 틀리거나 오래됐을 수 있다. 검토 결과를 형식 검사 성공이나 최근 조회 횟수로 올리지 않는다. 표시가 필요하면 실제 확인한 범위와 이유를 적고 임의 확률 점수를 만들지 않는다.

확인된 중요한 주장에는 실제 `verified_at`과 `verification`을 남긴다. 사용자 결정의 확인은 사용자 지시나 허용된 결정 주체의 확정 기록으로 판단한다. 외부 사실의 검증에는 관련 원자료·시험·관찰을 사용한다. 이 두 종류의 확인을 서로 대신 쓰지 않는다.

동일한 원문을 복제·재인용한 글은 하나의 출처 계보로 센다. 원본·공식 자료·직접 검증을 우선 검토하되 주장별 적용 범위를 확인한다. AI 요약이나 이전 위키의 설명이 스스로를 지지하는 순환 근거가 되지 않게 한다.

충돌은 먼저 대상·시점·버전·범위·용어 차이를 검토한다. 서로 다른 버전의 참인 설명은 적용 범위를 분리한다. 실제 대체 근거가 확인되면 교체하며, 판단할 수 없으면 양쪽 근거와 확인할 항목을 `disputed`로 남긴다. 최신 글이나 다수 출처라는 이유만으로 승자를 선택하지 않는다.

## 최신성과 증분 갱신

저장된 원자료의 해시 변경은 불변 보존 위반 또는 기록 오류다. 현재 입력의 해시 변경은 재처리 후보다. 서로 다른 형식이나 서로 다른 내용의 파일을 같은 해시 대상으로 비교하지 않는다.

원격 자료는 수집된 복사본과 현재 원격 상태를 구분한다. `refresh_due`가 지났다면 재확인 필요로 표시한다. 원격 접근 실패는 무변경이나 검증 성공이 아니다. 변동이 큰 현황·가격·버전·상태에는 필요에 맞는 재확인 시점을 정하고 지속적인 결정 이유에는 일률적인 만료를 강제하지 않는다.

원자료 변경·철회·확인 기한 도래 → 관련 주장 → 대표 문서 → 실제 `depends_on`·`implements` 관계를 따라 영향을 검토한다. 변경 탐지는 사실의 오류를 확정하지 않는다. 이미 처리한 해시는 영향을 확인하고 문서를 반영한 후에만 갱신한다. 변하지 않은 입력도 스키마·프로젝트 범위·반영 문서가 바뀌면 재검토할 수 있다.

파생 색인·검색·그래프가 오래됐으면 다시 구성한다. 레거시의 당시 내용은 갱신하지 않는다. 큰 문서 집합에서는 현재 작업·변경된 입력·그 의존 문서부터 검토하고 단계 종료나 정리 요청 때 더 넓게 점검한다. 전체를 검토하지 않고 전체가 최신이라고 주장하지 않는다.

## 통합·분리·결정 교체

**이력은 조용히 보존.** 유효한 오래된 문서는 유지한다. 레거시는 현행 답변·설계에 자동 섞지 않으며 과거 판단을 검토할 때 당시 자료임을 표시한다.

문서의 대표 목적·범위·독자·생애를 비교한다. 같은 주제라는 이유만으로 계획·요구사항·설계·일지·현재 상태를 합치지 않는다. 단어가 다르더라도 역할이 같고 중복이 크면 하나의 대표 문서로 통합한다.

통합 시 고유한 사실·근거·실패·미해결 쟁점을 유지한다. 대표 문서에는 현행 내용을 정리하고 통합 전 원본은 `legacy/<원래 종류>/`로 보존한다. 대표 ID를 유지하고 이전 ID·별칭·`merged_into` 관계를 연결한다. 날짜만 오래됐고 유효한 문서는 옮기지 않는다.

다른 판단에 필요한 내용이 한 문서에 과도하게 섞였으면 독립적인 목적별로 분리하고 상위 개요에서 연결한다. 고정 줄 수·최소 링크 수·단어 수를 맞추기 위해 쓸모없는 문서를 만들지 않는다.

결정 교체는 다음 순서로 수행한다.

1. 실제 확정된 새 결정에 이유·주체·적용 시점·영향·근거를 기록한다. 검토 중인 제안은 현행 결정을 대체하지 않는다.
2. 이전 결정은 `superseded`로 표시하고 새 결정 ID와 변경일·이유를 남긴 뒤 `legacy/decisions/`로 이동한다.
3. 새 결정은 `supersedes`로 이전 결정을 연결한다. 현재 설계·요구사항·진행 상태에서 새 결정의 영향을 확인한다.
4. 이전 결정 일부가 유효하면 현재 문서에 범위를 유지한다. 과거 문서 본문을 새 판단으로 다시 쓰지 않는다.

이동·이름 변경 뒤 문서 ID, 본문 경로, 근거 장부의 위치, 관계, 색인을 모두 복구한다. 외부 공유 경로에 필요하면 짧은 이동 안내를 둔다. 경로 충돌·동명 문서·대소문자 차이를 추측으로 해결하지 않는다.

원자료·작업일지·변경 로그·레거시는 요약했다는 이유로 삭제하지 않는다. 민감 정보의 철회나 명시적 삭제 요청은 보존 규칙보다 우선하며 파생 참조까지 범위를 확인한다.

## 구조 점검과 의미 검토

구조 점검은 문서 ID·링크·색인·해시·장부 정합성을 확인한다. [점검 도구](health-tool.md)는 읽기 전용이며 사실의 진실성은 검증하지 않는다. 같은 이름의 파일을 찾아 링크를 자동 추측하지 않는다.

의미 검토는 주장·출처 충돌, 역할 중복, 현재 코드와 설명의 차이, 누락된 연결, 순환 근거, 미확정 결정, 실패 기록 보존을 실제 읽기로 확인한다. 기본은 관련 범위이고 단계 완료·재개·정리 요청에서 범위를 넓힌다.

기계적으로 명확한 링크·색인 오류와 이미 허용된 통합은 고친다. 중요한 충돌의 확인 근거가 부족하면 미해결로 남기고 필요한 질문만 요청한다. 정리 작업을 근거 없는 사실 확정의 수단으로 사용하지 않는다.
